HTTP is inherently stateless, meaning every HTTP request is treated independently without built-in context regarding prior operations. To maintain application state across cycles—especially for user authentication and session tracking—applications rely on HTTP cookies and server-side sessions. When a user logs in, Django generates a unique session identifier stored in a server-side backend or database. Django then passes this session ID to the client via an encrypted browser cookie (sessionid). For every subsequent HTTP request, the client sends this cookie header automatically. Django reads the cookie, matches the ID against stored server session data, and reconstructs the authenticated user state. Supplemental techniques like JWT (JSON Web Tokens) encrypt identity payloads directly into client tokens to maintain stateless authentication across request cycles.

Deploying Django database migrations to a MariaDB relational database requires installing the mysqlclient engine package alongside the mariadb server daemon. Once MariaDB is installed, an administrator creates an isolated database instance and grants user access credentials. In settings.py, the default db.sqlite3 driver under DATABASES is replaced with django.db.backends.mysql, pointing to the MariaDB host, port, user credentials, and database name. Once configured, running python manage.py makemigrations scans model definitions to create migration files. Executing python manage.py migrate uses Django's ORM to translate those Python operations into MariaDB-compatible SQL statements, building tables, constraints, and relational schemas automatically on the production server.
